# PixieCore documentation

PixieCore documentation is grouped by responsibility so that product guidance,
runtime contracts, specifications, and project records do not share one flat
directory.

## Start here

- [Five-minute quickstart](guides/getting-started.md)
- [Blueprint tutorial](guides/tutorial.md)
- [Architecture guide](architecture/architecture.md)
- [POP Core Specification 0.1](specification/pop-core-specification-0.1.md)

## Documentation areas

| Directory | Responsibility |
|---|---|
| [`architecture/`](architecture/) | Runtime design, composition boundaries, class diagrams, and source documentation |
| [`blueprints/`](blueprints/) | Blueprint contracts, libraries, packages, publishing, evaluation, and demos |
| [`guides/`](guides/) | Getting started, tutorial, migration, and configuration guidance |
| [`plugins/`](plugins/) | Plugin lifecycle, authoring, layout, Recipes, Providers, and Tools |
| [`runtime/`](runtime/) | Runtime APIs, MCP, logging, telemetry, policy, review, caching, RAG, and JIT |
| [`integrations/`](integrations/) | Integration patterns and repository-owned examples |
| [`specification/`](specification/) | POP concepts, normative specification, schemas, conformance, and governance |
| [`project/`](project/) | Release policy, review policy, security, adoption, and release records |
| [`decisions/`](decisions/) | Accepted PixieCore architecture decision records |
| [`rfcs/`](rfcs/) | Proposed POP specification changes |

After source publication, public work is tracked in repository Issues. Private
readiness, migration, and historical implementation records are not part of the
public documentation tree.
