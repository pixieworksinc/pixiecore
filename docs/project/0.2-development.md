# PixieCore 0.2 development

PixieCore 0.2.x is the latest version line and recommended starting point for
new projects. It is available from the `0.2.x` source branch and is not yet
published on npm. Its goal is to restore
[prompt-first POP](../specification/pop-principles.md): business behavior,
including deterministic rules, is executed by the LLM.

## Initial milestone

- Restore prompt-first terminology in the primary concepts, granularity, and
  Blueprint-authoring guides.
- Accept structured ordered Scenario/Role prompts alongside existing text.
- Keep normalized `Blueprint.prompt` text compatible with existing Role plugins.
- Publish a distinct experimental PixieCore v2 schema; preserve v1 explicitly.
- Add an LLM-executed Customer discount example and an 18-case evaluation dataset.
- Test delivery, invalid declarations, bindings, and semantic-error detection.

## Recommended starting point

PixieCore 0.2.x is the latest version line and recommended starting point for
new projects. The published POP 0.1 schemas and
conformance fixtures remain historical artifacts for that portable profile;
they do not determine which PixieCore line new users should choose.

## Next milestones

1. Run repeated real-provider Customer discount evaluations and compare text
   Role decomposition with structured Scenario instructions under the same
   model, input corpus, and sampling settings. Report observed errors as well
   as accuracy, latency, and cost.
2. Adapt the travel-approval and invoice examples so that complete business
   policies can be expressed in Blueprints; measure each proposed decomposition.
3. Review the remaining catalog, scaffold defaults, conceptual diagrams,
   comparison benchmarks, and optional JIT path against the restored principles.
4. Complete the portable-model RFC and independent evidence without rewriting
   previously published POP identifiers.
5. Set the runtime package version and complete the normal release gates for a
   reviewed 0.2 candidate. Branch creation alone does not publish an npm release.

The package version stays at its inherited development value until release
preparation; neither a tag nor a published artifact is created by this milestone.

- `npm run test:coverage`: 932 tests, 931 passed, zero failed, one optional
  live-provider test skipped. Replay seed:
  `7627a910-5e62-4761-b662-746a39938993`.
- Scenario serializer line, branch, and function coverage: 100%.
- `npm run typecheck`, `npm run build`, `npm run check:source-docs`,
  `npm run check:api-docs`, and `npm run check:architecture`: passed.
- `npm run check:docs` and Blueprint version checks against the branch base:
  passed.
- Existing POP 0.1 runtime conformance and the independent Python validator:
  passed; no portable 0.1 artifact was modified.
- `npm run verify:package`: passed installation, declarations, schema exports,
  legacy schema access, native Scenario execution, and existing consumer smoke
  checks. The measured artifact has 527 files and 1,224,931 unpacked bytes.
  Its footprint limit increases by exactly the two new shipped files and an
  11,000-byte allowance for the schema, serializer, and authoring types.
- All 18 expected discount outcomes were independently checked with decimal
  arithmetic outside the production runtime.

These results verify implementation and evaluation mechanics. Real-provider
discount accuracy remains unmeasured.
