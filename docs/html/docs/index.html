PixieCore documentation

PixieCore documentation is grouped by responsibility so that product guidance, runtime contracts, specifications, and project records do not share one flat directory.

Start here

  • Recommended starting point for new projects: PixieCore 0.2.x, the latest development line, available from the 0.2.x source branch. No 0.2 npm release is published yet; the latest published package is 0.1.1. Starting a new project on 0.2.x does not require migration from an earlier release.

Documentation areas

Directory Responsibility
architecture/ Runtime design, composition boundaries, class diagrams, and source documentation
blueprints/ Blueprint contracts, libraries, packages, publishing, evaluation, and demos
guides/ Getting started, tutorial, application adoption, and configuration guidance
plugins/ Plugin lifecycle, authoring, layout, Recipes, Providers, and Tools
runtime/ Runtime APIs, MCP, logging, telemetry, policy, review, caching, RAG, and JIT
integrations/ Integration patterns and repository-owned examples
specification/ POP concepts, normative specification, schemas, conformance, and governance
project/ Release policy, review policy, security, adoption, and release records
decisions/ Accepted PixieCore architecture decision records
rfcs/ Proposed POP specification changes

Published HTML

The Markdown files remain the source of truth. Run npm run generate:html-docs to refresh the browsable HTML in docs/html/, and npm run check:html-docs to verify that the generated files match the current sources. The published documentation is available at https://pixieworksinc.github.io/pixiecore/docs/html/.

After source publication, public work is tracked in repository Issues. Private readiness, migration, and historical implementation records are not part of the public documentation tree.
